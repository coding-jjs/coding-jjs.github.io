Architecture

브라우저 요청은 proxy.ts에서 역할에 맞지 않는 URL을 먼저 막습니다. 페이지는 src/app의 역할별 라우트로 들어가고, 조회/변경은 src/features로 모읍니다. 쓰기는 Server Action 진입 때 권한을 다시 확인하고, Prisma·Gemini·스토리지로 이어집니다.

Design notes

역할은 원장이 부여. 가입자가 역할을 고르면 권한 사고가 나기 쉬워, Google 가입 후 GUEST로 두고 원장이 부여하도록 만들었습니다.

권한은 라우트 + PermissionGrant. 역할별 홈으로 진입을 나누고, 교사·직원 세부 기능은 부여 단위로 켰다 끄게 했습니다.

AI는 초안 후 승인. Gemini 리포트를 바로 보내지 않고 검토 흐름을 두어 운영 리스크를 낮췄습니다.

배포까지 문서화. Next.js standalone + Docker + Lightsail/Caddy 초안을 deploy/에 남겨 앱 구조와 배포 경로를 같이 보이게 했습니다.
